# App-Install Campaigns

## Overview

Paid campaigns whose goal is an **install of the Jetcost app**, not a
visit to the web site. Two platforms:

- **Google Ads app campaigns** — installs from the Play Store and the
  App Store, run in Google Ads next to the SEM accounts.
- **Apple Search Ads** — ads in the App Store's own search results.

There is no other platform buying installs.

## What they optimise on

The Google campaigns optimise on install signals (first opens) that
carry **no economic value**: they count an install, they do not price
it (see the App Install Signals of
[sem/google-ads.md](/core/marketing/sem/google-ads.md)). The same
signals are also part of the web Search campaigns' conversion goal,
because a web user pushed to install the app is a result Jetcost wants
(see [core/product/w2a/index.md](/core/product/w2a/index.md)).

## How to read them

An install produces no revenue by itself: the value of these campaigns
is what the installed users bring over the following weeks and months,
so they are judged on the install cohort — First Opens and ARPU per
cohort in [core/product/metrics.md](/core/product/metrics.md) — not on
the sessions or the revenue of the day the money is spent. Comparing
their cost with same-day revenue, as one would for SEM, makes them look
worse than they are.

Installs come from three directions — these campaigns, the web pushing
its users to the app (W2A) and organic store discovery — so a change in
installs is not by itself a change in these campaigns.
